`ViewportGizmo` now runs on the 3.0 modules. Every click, drag and turn writes the camera through one pose write: `camera.position`, `camera.quaternion` and `camera.up`, then tells the attached controls about a new up. Events follow the 3.0 contract: `press` (`{ pressed }`) for every accepted press, `start`, `change` and `end` keyed by `cause` (`click`, `drag`, `key`, `navigation`, `api`) with a heading, a pose `{ direction, up }` and an outcome (`reached`, `interrupted`, `cancelled`, `unavailable`), `hoverchange` (`{ hovered }`, also when a turn moves a target under a still pointer), `attargetchange` and `invalidate`, which a render-on-demand host can render from alone. `end` balances `start` under `cancel()`, `pointercancel`, `enabled = false`, a structural `set()` and `dispose()`. `update()` no longer steps the controls, so it is safe inside a controls `change`; `render()` measures the gizmo's rectangle itself. State is read-only: `options`, `targets`, `hovered`, `dragging`, `animating`, `heading`, `atTarget`, `up`, `canRoll`, `viewport`; `enabled` is an accessor. The label up defaults to `camera.up` snapped to its nearest axis. The removed 2.x members `domUpdate()`, `cameraUpdate()`, `placement`, `animated` and `speed` throw `ViewportGizmoError` with code `REMOVED_MEMBER`, naming the replacement; constructing without a `document` throws `DOCUMENT_MISSING`.
